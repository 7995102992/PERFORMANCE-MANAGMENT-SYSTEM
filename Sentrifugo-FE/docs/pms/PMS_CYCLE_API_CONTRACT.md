# PMS Cycle — API Contract (for backend)

Screens covered: **1.1 PMS Cycle list · 1.2–1.5 Initiate Appraisal wizard · 1.6 Cycle Activated**.

The frontend currently runs on static mock data. Every endpoint below is already
wired in [`src/store/api/pmsApi.ts`](../../src/store/api/pmsApi.ts) behind a
`queryFn`; going live is a one-line swap per endpoint (replace `queryFn` with the
commented `query`). Request/response TypeScript types are in
[`src/types/pms.ts`](../../src/types/pms.ts) — treat them as the schema.

## Conventions

- Base URL: `VITE_PMS_API_BASE_URL` (e.g. `http://localhost:8006`). Auth: `Authorization: Bearer <access_token>`, same as the other services.
- `organisation_id` is **not** sent by the client — take it from the session.
- Dates are `YYYY-MM-DD`; timestamps are ISO-8601.
- Errors: `{ "detail": "<human message>", "code": "<MACHINE_CODE>" }`. The UI branches on `code`, never on `detail`. 422 for validation, 404 not found, 409 invalid state transition.
- `cycle_code` (`PMS-2627-A`) is generated by the server: `PMS-{FYstart yy}{FYend yy}-{A|M|C}` for Annual / Mid-Year / Custom, with a numeric suffix (`PMS-2627-A2`) when the code is taken.

### 1. `GET /pms/cycles`

Query: `search` (matches cycle code or name), `year` (FY start, `2026` = FY 2026-27, matched on `period_start`), `type` (`annual|mid_year|custom`), `plant_id`, `status` (`draft|active|closed|cancelled`), `skip`, `limit`. Sort: newest `created_on` first.

```json
{
  "items": [{
    "id": "cyc-2627-a", "cycle_code": "PMS-2627-A", "name": "FY 2026-27 Annual Appraisal",
    "type": "annual", "period_start": "2026-04-01", "period_end": "2027-03-31",
    "applicable_to": "All Plants", "status": "draft", "created_on": "2026-04-18"
  }],
  "total": 6,
  "summary": { "all": 6, "draft": 1, "active": 1, "closed": 3, "cancelled": 1 }
}
```

- `total` is the count **after** all filters including `status` (drives pagination).
- `summary` counts honour every filter **except `status`**, so the stat cards stay stable while a status tab is selected.
- `applicable_to`: `"All Plants"` when every plant is covered, otherwise comma-joined plant names.

### 2. `GET /pms/cycles/{cycle_id}` → `PmsCycle`

```json
{
  "id": "cyc-2627-a", "cycle_code": "PMS-2627-A", "status": "draft",
  "created_on": "2026-04-18", "published_on": null, "applicable_to": "All Plants",
  "basic":  { "name": "FY 2026-27", "description": "…", "type": "annual",
              "period_start": "2026-04-01", "period_end": "2027-03-31" },
  "stages": [ { "stage": "goal_setting", "start_date": "2026-05-01", "end_date": "2026-05-20", "notify": true } ],
  "applicability": {
    "plant_ids": ["plant-mattampally"], "all_departments": true, "department_ids": [],
    "employment_types": ["permanent"], "min_service_months": 12, "service_as_on": "2026-04-01",
    "exclude_probation": true, "exclude_notice_period": true
  },
  "finalize": { "rating_scale_id": "scale-5", "notify_managers": true,
                "notify_employees": true, "notify_hod": true, "notify_hr": true }
}
```

### 3 & 4. `POST /pms/cycles` · `PUT /pms/cycles/{cycle_id}`

Body = `PmsCycleUpsert` = `{ basic, stages, applicability, finalize }` (shapes as above, without the server fields). Response = the saved `PmsCycle`.

- **Draft saves are partial.** The UI's "Save as Draft" sends the whole body but only guarantees `basic` is valid: `stages` may hold default dates, `applicability.plant_ids` may be `[]`, and `finalize.rating_scale_id` may be `""`. Validate strictly only on `publish`.
- `PUT` is allowed while `status` is `draft` or `active`; otherwise `409 PMS_CYCLE_NOT_EDITABLE`.
- Validation: `period_end > period_start`; each stage `end_date >= start_date`; `stage` is one of the fixed keys below, each at most once.

Fixed stage keys, in process order:
`goal_setting`, `employee_acknowledgement`, `hod_approval`, `progress_tracking`, `mid_year_review`, `self_appraisal`, `manager_appraisal`, `hod_review`, `calibration_final_approval`.

### 5. `POST /pms/cycles/{cycle_id}/publish` → `PmsCycleActivation`

No body. Must re-validate the full cycle strictly (≥1 plant, ≥1 employment type, departments when `all_departments` is false, a valid `rating_scale_id`, all stage dates present) → `422` otherwise. `409 PMS_CYCLE_NOT_PUBLISHABLE` unless `status = draft`. On success: set `status = active`, stamp `published_on`, start the eligibility run, send notifications to the groups ticked in `finalize.notify_*`.

```json
{
  "cycle": { "…": "PmsCycle with status=active" },
  "published_on": "2026-04-30",
  "notifications": [
    { "audience": "hod_reviewers", "sent": 14 },
    { "audience": "reporting_managers", "sent": 68 },
    { "audience": "employees", "sent": 1102 }
  ]
}
```
`audience` ∈ `hod_reviewers | reporting_managers | employees | hr`. Only include groups that were notified.

### 6. `GET /pms/cycles/{cycle_id}/activation` → `PmsCycleActivation`

Same shape as above, so screen 1.6 survives a refresh. `409 PMS_CYCLE_NOT_PUBLISHED` while the cycle is still a draft.

### 7. `POST /pms/cycles/{cycle_id}/cancel` → `PmsCycle`

`draft` or `active` → `cancelled`. No UI button yet; kept so the list's Cancelled status has a transition.

### 8. `GET /pms/cycles/export`

Same query filters as #1, without `skip`/`limit`. Return a file with `Content-Disposition: attachment; filename=…`. Columns: Cycle ID, Cycle Name, Type, Period Start, Period End, Applicable To, Created On, Status.

### 9. `POST /pms/cycles/eligible-employees/preview`

Body: the `applicability` object. Response:

```json
{
  "total_eligible": 42,
  "excluded_probation": 3, "excluded_notice_period": 1, "excluded_min_service": 6,
  "items": [{ "employee_id": "…", "employee_code": "SC1006", "name": "Priya Kumar",
              "department": "IT", "plant": "Mattampally",
              "employment_type": "permanent", "service_months": 38 }]
}
```
`items` is the first 25 eligible employees only — a preview, not a roster. `service_months` is measured to `service_as_on`.

### 10–12. Lookups

```json
GET /pms/lookups/plants        → [{ "id": "plant-mattampally", "name": "Mattampally" }]
GET /pms/lookups/departments   → [{ "id": "dept-production", "name": "Production" }]
GET /pms/rating-scales         → [{ "id": "scale-5", "name": "Standard 5-Point Scale",
                                    "levels": [{ "value": 5, "label": "Outstanding",
                                                 "description": "Exceptional performance" }] }]
```
Rating `levels` are returned highest value first.

## Status lifecycle

```
draft ──publish──▶ active ──(cycle closure, later screen)──▶ closed
  └──────────cancel──────────┘▶ cancelled
```
`closed` and `cancelled` cycles are read-only in the UI (the edit action is disabled and edit links redirect to the view page).
